## Security and integrity work

- Mock mode uses only the mock client; unverified mock webhook acceptance is gated by `ALLOW_UNVERIFIED_WEBHOOKS_IN_MOCK` and mock mode never contacts PayPal.
- PayPal webhook verification preserves the original event JSON bytes, stores verification/processing outcomes, deduplicates event IDs, limits payload size, and re-fetches provider state before applying order/capture changes.
- Payment create is idempotent for an existing live order; DB uniqueness remains the concurrency backstop. Capture/cancel/sync lock payment rows where supported.
- Order and capture amount/currency are checked against the database amount. Mismatch is audited and persisted as `FAILED`; milestones are not marked paid.
- Definitive provider 4xx capture errors become failed/denied states. Ambiguous timeout/5xx outcomes remain reconcilable by sync/webhook.
- Project membership is checked for reads, ledger access, and sync; capture and cancel remain payer-only.
- The payment live-row index now has matching SQLite and PostgreSQL predicates so terminal payments can be retried in both test and production databases. No migration was changed.
